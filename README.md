面向高校保卫处新值班员和辅导员的单人训练工具。以夜间宿舍火灾为例，学员会在地图上看到通道积水，也会收到位置含糊、相互重复的模拟上报。学员需要辨别线索、选中楼栋、安排处置。结束后可以沿时间线查到哪一步得分、哪项遗漏，以及当时有哪些信息可用。

## 如何体验

验收时请一位未参与开发的人独立完成以下五步。**「3 分钟以内」是待测目标，不是已验证事实**——实测安排见 [`docs/quality-verification.md`](docs/quality-verification.md)。

1. 打开公开链接，阅读首屏训练声明，免登录点击「开始一次推演」。
2. 选择一张预置场景卡，或点击「AI 随机生成」（每会话限 3 次）。
3. 信息流按时间轴**分批**出现模拟上报（每轮 10 条）。**每条出现后即可判读**：真报 / 误报 / 待核，判为真报的可再点选楼栋定位（「无法定位」是合法答案）。**不必等整批出现，也不必判完才能行动。**
4. 点击楼栋，选择派队、警戒、广播疏散等动作，观察资源和路线变化。可加速推进，也可根据新线索再次行动或改判。
5. 末回合对整批上报做**一次**优先级排序（选出最紧急的 3 条）。结束推演后**立即**看到分项得分、失误对应的动作与时间线；AI 点评异步补入。本轮自动留痕，可按推演编号导出 JSON，并在本地「我的档案」回看。

> **关键设计**：「待核」不等于不作为。证据不足时的最优策略是**判待核 + 立即派核查动作**——这样既拿甄别分，也拿响应速度分。详见 [`docs/requirements.md`](docs/requirements.md) 的手算样例。

## 交付范围

三个模板覆盖 **夜间宿舍楼火灾与暴雨内涝**、**实验室危化品泄漏与人员失联**、**体育馆散场踩踏风险与通讯中断**。每模板规定起始楼栋、恶化条件、至少两个意外变量、标准动作和关键待办。夜间、暴雨、通讯中断、人流高峰作为干扰因子，以场景卡上的开关提供。另备 **2 个完整案例**供免登录体验，并支持载入已完成的一轮作演示。

| 优先级 | 功能 | 验收时观察什么 |
| --- | --- | --- |
| P0 · F1、F6 地图与路径 | 单校区 20 栋楼，记录类别、估算容量、风险和邻接关系，叠加灾情点、警戒区、救援队 | 桌面和 375px 手机均能选中楼栋。封闭一段道路后地图标出阻断，路线重算 |
| P0 · F2、F3 剧本与时间轴 | 按模板生成带意外变量的剧本，按节点分批注入事件，可调整速度 | 同一模板两次生成可出现不同情节；加速不改变模拟时间 |
| P0 · F4、F5 模拟上报 | 每轮 10 条，覆盖真报、误报、情绪化、位置模糊、重复五类，保存事后真值与**分时段合理判断** | 提交后即时反馈，参考答案作答后揭示；「待核」在证据不足时判对 |
| P0 · F7 处置动作 | 6 种：上报核查、派队、警戒、广播疏散、封路、断电。每种定义对象、前置条件、耗时、资源 | 前置条件缺失或资源冲突时说明拒绝原因并留痕 |
| P0 · F8、F9 评分与单次复盘 | 完整决策流水，固定规则算四项指标，生成时间线、亮点、失误、建议 | 刷新或重算得分一致；点评定位到具体动作；**临场换个动作分数会变** |
| P0 · F10、F14、F15 体验与演示 | 免登录、2 个完整案例、训练水印、逐条上报徽标、一键载入已完成推演 | 任意截图可识别训练属性；预录入口明确标注「示例回放」 |
| P1 · F11 我的档案 | 本地会话列表，展示时长、总分、主要失误类型，支持按编号导出 JSON | 可回看本机多轮记录 |

**本期不做**：趋势折线、独立导调面板、跨会话持久化看板、多人协作或对抗、室内导航、现场指挥、真实设备或通信对接、跨机构案例检索、账号权限体系。训练效果的统计验证留待赛后研究。

## 双人双轨并行

两人各自拥有可独立验证的交付物，不存在一方等待另一方接口的情形。

| | A · 引擎轨 | B · 界面轨 |
| --- | --- | --- |
| 职责 | 楼栋与路段数据、Dijkstra、规则引擎、评分器、Agent 三类生成与兜底、Sites 建表读写与导出 | SVG 地图与图层、推演页布局、时间轴 UI、信息流与甄别交互、动作面板、复盘页、档案列表、部署与性能、视频与作品帖 |
| 运行环境 | Node / CLI，**不需要浏览器** | 浏览器，**不需要 A 的引擎或数据库** |
| 数据来源 | 真实 DB 与 Agent | **D1 冻结的 fixture**，D6 才替换 |
| 独立里程碑 | **D4**：同一固定剧本、两种选择、两份可解释的不同结果，实时算出 | **D5**：fixture 版部署公网，请同学试用并记录实际用时 |
| 验收方式 | 单元测试 + CLI 输出 | 浏览器实操 + 控制台检查 |

**同步点仅三处**：

1. **D1 上午 2 小时 · 契约冻结**。共同产出并锁定 `src/contracts.ts` 类型、`fixtures/` 假数据、数据表 DDL、评分权重与模拟时钟规则。
   **D1 最重要的共同交付是「一轮双方都能手算的样例」**：同一条「待核」上报、同一次核实、两种不同处置，各自对应明确的得分与复盘理由。完整定义见 [`docs/requirements.md` §5](docs/requirements.md)。A 用它验证引擎，B 用它验证界面，D6 联调时即有共同判断依据。
2. **D6 · 集成日**。B 把 fixture 数据源替换为 A 的引擎与 DB 调用。契约已冻结，集成是「换数据源」而非「重写」。
3. **D8 · 联调验收与材料分工**。

契约变更须双方确认并同步更新 fixture。数据表结构 D2 结束前冻结，之后只做增量变更。

## 检查点与降级

| 时点 | 判据 | 不达标时的降级动作 |
| --- | --- | --- |
| 🔴 **D1 晚** | Sites 建表 / 读写 / Agent 调用连通 | **DB 不通**：A 改本地 JSON + 浏览器 localStorage，契约不变，B 不受影响，README 如实说明持久化位置。**Agent 不通**：剧本、上报、复盘全部预置入库，B 完全不受影响 |
| 🔴 **D4 晚** | **同一固定剧本、两种选择、两份可解释的不同结果，且为实时计算** | **A 轨不通**：A 优先保住动作判定与评分器，B 接入同一剧本；其余功能让位。**B 轨不通**：以 A 的 CLI 引擎 + 极简表单页降级为对话式推演，保留噪声甄别、评分、复盘，记录受影响的地图验收项。**若最终只能播放预录结果**：入口明确标注「示例回放」，不得宣称支持临场决策 |
| 🔴 **D7 晚** | 公网可访问 + 五步实测用时达标 + 桌面与移动控制台 0 报错 | 移除 F11 档案列表，预置案例减为 1 个，砍除演示模式外的全部装饰 |

D4 判据之所以强调「实时计算、两份不同结果」，是因为**预置流水只能证明一次既有结果，无法证明评委临场换个动作后分数也会变化**。这是降级预案最容易自欺的地方。

## 训练数据与使用声明

首屏及视频开头展示训练声明。所有页面使用训练水印，每条模拟上报显示「训练模拟数据」。

> 本系统仅用于桌面推演训练。灾情和学生上报均为模拟数据，存放于独立训练数据表。AI 输出仅供本轮推演讨论。系统与真实报警、监控、传感器及指挥通信渠道隔离。

数据来源、脱敏方式与精度声明见 [`docs/requirements.md` §6](docs/requirements.md)。
