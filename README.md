## 如何体验

当前本地版本用 Node 24 执行 `npm ci`、`npm run build`、`npm run preview`。从「推演」选择模板并开始预置训练。模拟生成和回退的启动方式见 [D5 交接](docs/handoff-d5.md#运行与部署)。

验收时请一位未参与开发的人独立完成以下五步。**「3 分钟以内」是待测目标，不是已验证事实**——实测安排见 [`docs/quality-verification.md`](docs/quality-verification.md)。

1. 打开公开链接，阅读首屏训练声明，免登录点击「开始一次推演」。
2. 选择一张预置场景卡，或点击「AI 随机生成」（每会话限 3 次）。
3. 信息流按时间轴**分批**出现模拟上报（每轮 10 条）。**每条出现后即可判读**：真报 / 误报 / 待核，可为已出现的上报选择位置或「无法定位」，包括判断为「待核」的上报。**不必等整批出现，也不必判完才能行动。**
4. 点击楼栋，选择派队、警戒、广播疏散等动作，观察资源和路线变化。可加速推进，也可根据新线索再次行动或改判。
5. 末回合对整批上报做**一次**优先级排序（选出最紧急的 3 条）。结束推演后**立即**看到分项得分、失误对应的动作与时间线；AI 点评异步补入。本轮自动留痕，可按推演编号导出 JSON，并在本地「我的档案」回看。

> **关键设计**：「待核」不等于不作为。证据不足时的最优策略是**判待核 + 立即派核查动作**——这样既拿甄别分，也拿响应速度分。详见 [`docs/requirements.md`](docs/requirements.md) 的手算样例。

## 交付范围

三个模板覆盖 **夜间宿舍楼火灾与暴雨内涝**（落点：萃园北区 N7 等宿舍 + 北一/北二食堂 + 3 号门）、**实验室危化品泄漏与人员失联**（基础实验楼 + 工程实践中心 + 门诊部）、**体育馆散场踩踏风险与通讯中断**（天健苑体育中心 + 学海苑教学区人流）。每模板规定起始楼栋、恶化条件、至少两个意外变量、标准动作和关键待办。夜间、暴雨、通讯中断、人流高峰作为干扰因子，以场景卡上的开关提供。另备 **2 个完整案例**供免登录体验，并支持载入已完成的一轮作演示。

**地图使用真实校名与真实分区**（萃园/润园/学海苑/至行苑/文博苑/天健苑等），学员练的是本校值班员真会听到的地名；但**平面位置、轮廓、容量与风险标注均为训练级模拟设定**，详见 [`docs/requirements.md` §6～§7](docs/requirements.md)。

## 双人双轨并行

A 负责可在命令行和浏览器复用的推演规则，B 负责在网页呈现同一轮决策。D1 至 D5 可用同一套剧本数据并行开发。D4 的临场改分依赖 A 的评分函数，D6 的保存与恢复依赖双方约定的读写接口。

| | A · 引擎轨 | B · 界面轨 |
| --- | --- | --- |
| 职责 | 楼栋与路段数据、Dijkstra、规则引擎、评分器、Agent 三类生成与兜底、Sites 建表读写与导出 | SVG 地图与图层、推演页布局、时间轴 UI、信息流与甄别交互、动作面板、复盘页、档案列表、部署与性能、视频与作品帖 |
| 运行环境 | Node / CLI 验证核心逻辑，供浏览器调用的规则与评分函数保持可移植 | 浏览器可用内置剧本开发界面。D4 联合验收时使用 A 的评分函数 |
| 数据来源 | 固定样例用于评分回归，Sites 与 Agent 用于连通性验证 | D1 约定的样例驱动交互，D4 接评分函数，D6 接真实读写 |
| 独立里程碑 | **D4**：同一固定剧本、两种选择、两份可解释的不同结果，实时算出 | **D5**：fixture 版部署公网，请同学试用并记录实际用时 |
| 验收方式 | 单元测试 + CLI 输出 | 浏览器实操 + 控制台检查 |

**交接安排**

1. **D1 上午 2 小时 · 契约冻结**。共同产出并锁定 `src/contracts.ts` 类型、`fixtures/` 假数据、数据表 DDL、评分权重与模拟时钟规则。建筑数据按 [`requirements.md` §7](docs/requirements.md) 落地：D1 交付 **8 栋 fixture**（N7、N1、N2、N11、CN1、CN2、GYM、LIB + GATE3 + 8 条路段），A 于 D2 补齐 20 栋，**只增数据不改结构**。
   **D1 最重要的共同交付是「一轮双方都能手算的样例」**：同一条「待核」上报、同一次核实、两种不同处置，各自对应明确的得分与复盘理由。完整定义见 [`docs/requirements.md` §5](docs/requirements.md)。A 用它验证引擎，B 用它验证界面，D6 联调时即有共同判断依据。
2. **D4 · 验证临场改分**。A 提供可复用的判定、评分函数与分项明细，B 把界面动作传入该函数。推荐分支、失误分支及临场补做动作都走同一计算入口。具体手算样例需先解决下列冲突。
3. **D6 · 集成日**。A 提供按轮次保存、读取和导出流水的接口，B 负责调用及下载入口。先以固定剧本测试开始、行动、保存、刷新、重算、导出，再接当天生成的上报。
4. **D8 · 试用与材料**。A 导调并整理本轮流水、评分说明及数据出处，B 录屏并保存同一编号。建议将视频剪辑排到 D9，D8 先取得可用素材。

契约变更须双方确认并同步更新 fixture。数据表结构 D2 结束前冻结，之后只做增量变更。
