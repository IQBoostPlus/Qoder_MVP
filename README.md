# 校园应急桌面推演训练沙盘

面向高校保卫处新值班员和辅导员的单人训练工具。以夜间宿舍火灾为例，学员会在地图上看到通道积水，也会收到位置含糊、相互重复的模拟上报。学员需要辨别线索、选中楼栋、安排处置。结束后可以沿时间线查到哪一步得分、哪项遗漏，以及当时有哪些信息可用。

## 如何体验

验收时请一位未参与开发的人独立完成以下五步，从打开页面到看见本轮复盘，目标为 **3 分钟以内**。

1. 打开公开链接，阅读首屏训练声明，免登录点击「开始一次推演」。
2. 选择一张预置场景卡，或点击「AI 随机生成」。
3. 查看地图与随时间出现的信息流，为模拟上报判断真伪、标记优先级并定位楼栋，查看即时反馈。
4. 点击楼栋，选择派队、警戒、广播等动作，观察资源和路线变化。可加速推进，也可根据新线索再次行动。
5. 结束推演，查看分项得分、失误对应的动作及点评。本轮自动留痕，可按推演编号导出 JSON。启用「我的档案」后，可从列表回看历次推演。

## 场景与交付范围

三个模板分别覆盖 **夜间宿舍楼火灾与暴雨内涝**、**实验室危化品泄漏与人员失联**、**体育馆散场踩踏风险与通讯中断**。每个模板规定起始楼栋、恶化条件、至少两个意外变量、标准动作和关键待办。夜间、暴雨、通讯中断、人流高峰可作为干扰因子组合。模板决定可以生成什么，另备 **4 个完整案例**供免登录体验，并支持直接载入已完成的一轮作演示。

| 优先级 | 功能 | 验收时观察什么 |
| --- | --- | --- |
| P0 · F1、F6 地图与路径 | 单校区至少 25 栋楼，记录类别、估算容量、风险和邻接关系，叠加灾情点、警戒区、救援队 | 桌面和 375px 手机均能选中楼栋。封闭一段道路后，地图标出阻断，路线重算 |
| P0 · F2、F3 剧本与时间轴 | 按模板生成带意外变量的剧本，按节点注入事件，可调整速度 | 同一模板两次生成可出现不同情节，时间轴能自动推进并加速 |
| P0 · F4、F5 模拟上报 | 每轮 10～15 条，控制真报、误报、情绪化、位置模糊、重复五类分布，保存真伪、优先级和位置参考标签 | 学员提交判断后得到即时反馈。原始文字可回看，参考答案在作答后揭示 |
| P0 · F7 处置动作 | 至少 8 种，每种定义对象、前置条件、耗时和资源消耗。拟用派队、警戒、断电、上报、广播、疏散、封路、核查 | 前置条件缺失或资源冲突时，说明拒绝原因并留痕 |
| P0 · F8、F9 评分与单次复盘 | 保存完整决策流水，用固定规则算四项指标，生成时间线、亮点、失误和建议 | 刷新或重算得分一致。点评可定位到具体动作，遗漏可查到相应待办 |
| P0 · F10、F14、F15 体验与演示 | 免登录、4 个完整案例、训练水印、逐条上报徽标、一键载入已完成推演 | 任意页面截图可识别训练属性。现场可直接用预置流水展示完整复盘 |
| P1 · F11、F13 | 「我的档案」展示时长、总分、主要失误，另设默认折叠的导调面板 | 可回看多轮记录，或手动叠加干扰因子、注入意外 |
| P2 · F12 | 三点趋势折线与 3 条明确标注的示例记录 | D9 有余力再做，示例记录与本人推演可区分 |

## 技术架构与 AI 边界

首版拟采用 React + TypeScript 构建一个响应式网页应用，由 Qoder Sites 托管。一次推演按“选剧本 → 注入事件 → 学员行动 → 规则判定并记录 → 评分与复盘”推进。AI 担任导调员，学员用同一界面完成训练。

| 模块 | 拟用技术 | 责任边界 |
| --- | --- | --- |
| 地图与交互 | React、SVG、GeoJSON | 桌面左右分栏，手机上下排列。地图呈现楼栋、资源和路径，信息流呈现学员当时可见的线索 |
| 剧本与上报 | Qoder Cloud Agent、JSON Schema | 输入模板、干扰因子和已入库楼栋，生成起始位置、时间轴、模拟上报生成指令、关键项及标准动作。校验楼栋 ID 和动作目录后才载入 |
| 路径与动作 | TypeScript、邻接图、Dijkstra | 阻断路段权重设为无穷大，重新求可用路径。规则引擎检查对象、前置条件和资源，记录接受或拒绝及原因 |
| 留痕与评分 | Qoder Sites 数据库、共享 TypeScript 评分函数 | 前后端复用同一份规则和常量，按推演编号和动作顺序重算。浏览器本地会话用于免登录体验 |
| 单次复盘 | 确定性评分明细、Cloud Agent | 依据流水和标准流程生成 highlights、mistakes、suggestions。每条点评引用动作序号，提示词与输出过滤限定为本轮训练讨论 |

**每轮最多 4 次模型调用**，预算分给剧本、整批上报、复盘各一次，全轮共享一次重试。结构不合法或引用未知楼栋时，丢弃无效结果，在预算内重试一次。仍未通过就载入同模板的预生成剧本。上报和复盘也准备预置上报批次、基于得分明细的文字摘要，断开 Agent 后仍能完成训练。模型调用计数随轮次记录。

## 评分与复盘依据

以下为 **D2 待确认的候选权重和换算规则**。v2 规定了指标、百分制与可重算要求，具体权重由团队定稿。四项分数均在 0～100 之间，候选总分为四项加权和，最后四舍五入取整数。

| 指标 | 候选权重 | 建议换算 |
| --- | ---: | --- |
| 上报甄别准确率 | 30% | 依据每条上报的真伪、优先级和楼栋标签核对，三项全对记 1 条正确。得分为正确条数 ÷ 本轮全部上报数 × 100，未判计 0 |
| 首报有效响应时长 | 20% | 从第一条真事件上报出现，到首次针对该事件且通过规则的动作，按模拟时间求差。暂定 30 秒以内满分，30～120 秒线性降至 0，超过 120 秒或未响应计 0。剧本须含真报 |
| 标准动作命中率 | 35% | 对照剧本逐项匹配成功动作，关键项权重暂定为 2，普通项为 1。得分为已命中权重 ÷ 全部标准项权重 × 100，每项只计一次 |
| 违规与遗漏 | 15% | 同时展示两项原始计数。候选分项从 100 分起，每次违规扣 10 分，每个结束时未完成的关键项扣 20 分，最低 0 分 |

例如四项分别得到 80、100、80、60 分，候选总分为 **81 分**。复盘展示各项得分及原始依据。被拒动作保留尝试序号，关键遗漏挂在本轮结束核对节点，并引用缺失项。计时使用记录中的模拟时间，使刷新、回放和前后端重算使用同一输入。评分器与规则引擎须写单元测试，至少验证相同流水同分、关键项仅计一次、前置条件与资源冲突的拒绝结果。

## 训练数据与使用声明

首屏及视频开头展示训练声明。所有页面使用训练水印，每条模拟上报显示「训练模拟数据」。

> 本系统仅用于桌面推演训练。灾情和学生上报均为模拟数据，存放于独立训练数据表。AI 输出仅供本轮推演讨论。系统与真实报警、监控、传感器及指挥通信渠道隔离。

| 数据 | 计划来源与处理 |
| --- | --- |
| 楼栋与道路 | D1 核查南京工程学院的 OpenStreetMap 楼栋覆盖情况。采用时记录来源、署名和覆盖范围。覆盖不足则手绘至少 25 栋的简化 GeoJSON，标注「训练级精度，楼栋位置人工绘制」。容量、风险标签及阻断条件均注明模拟设定 |
| 剧本与上报 | 团队编制训练模板，由 Agent 生成剧本与噪声文字，保存各条参考标签。首版拟使用合成语料。如引入真实校园语料，先记录来源、移除姓名、联系方式及可识别细节，再说明改写方式 |
| 轮次与证据 | 单独保存训练上报，固定 is_training = 1。按 run_id 导出完整事件与判定，用于演示和复盘。试用材料标明实际参与者的角色，示例数据单独标识 |

数据表按职责分为 **campus_buildings、disaster_templates、action_catalog**（楼栋、模板、动作目录），**scenarios**（生成或预置剧本），**runs、run_events、ugc_reports**（轮次、带顺序与模拟时间的事件、训练上报）。D2 结束前冻结结构，之后只做增量变更，由 A、C 确认。

**未覆盖范围**包括多人协作或对抗、室内导航、现场指挥、真实设备或通信对接、跨机构案例检索和账号权限体系。训练效果的统计验证留待赛后研究。本届展示的是每轮操作及评分依据。

## 验收与参赛材料

- **可用性与性能**　以无痕窗口和手机打开 public 站点。未参与开发的人能在五步、3 分钟内完成推演。375px 下可点选楼栋并操作信息流，键盘可操作动作按钮，颜色变化附文字，对比度目标 WCAG AA。D7 起每轮检查桌面和移动端控制台 0 报错。用 Lighthouse 和计时实测首屏 < 3 秒、剧本生成 < 15 秒，等待过程有进度提示。
- **工程验收**　测试路段阻断、非法动作、刷新重算、按编号导出 JSON、Agent 中断后的完整推演，以及每轮调用次数。单页代码控制在 300 行以内，权重、动作与模板参数独立保存。地图图层延迟加载，信息流超过 30 条时启用虚拟滚动。
- **视频与试用**　准备约 3 分钟演示视频，展示训练声明、痛点、剧本生成、学员决策、复盘与档案。另交至少一场 30 分钟真人微推演录屏及其流水 JSON。
