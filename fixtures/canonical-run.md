# D1 标准样例手算说明（v4.1 真实校区数据）

配套数据：[`canonical-run.json`](canonical-run.json)；地图投影：[`buildings.json`](buildings.json)。本文件与 JSON 使用同一套时刻、尝试序号与分数口径。B 可直接按本表复算，再用 [`../scripts/validate-canonical.ts`](../scripts/validate-canonical.ts) 对照机器结果。

- 样例：**8 栋真实选点**（N7、N1、N2、N11、CN1、CN2、GYM、LIB）、**1 个路口**（GATE3）、**8 条路段**、1 个固定剧本、10 条模拟上报、6 种动作、3 份流水。
- 三条流水：甲 **83**、乙 **44**、甲补做 A4 **90**。
- 起始楼栋 **N7（萃园 7 幢 / 北 7）**，阻断路段 **R-N7E（北 7 东侧至 3 号门）**。
- 所有判读、改判与动作提交时刻都是剧本节点（FR-4.7），可由 1× 或 4× 播放到达；加速只压缩真实等待，不改变 `t_sim`。
- 生产评分器在 D4 交付。本文件与校验器只用于 D1 契约回归。

- 命中 A2（权重 3）、A3（权重 2），合计 5；漏 A1、A4、A5、A6。
- A2 与 A3 分别占用 `rescue_team` 与 `barrier_team`，并行合法，且同时于 280 完成。

| 指标 | 依据 | 得分 |
| --- | --- | ---: |

## 7. 甲补做 A4 → 90 分

在分支甲基础上，于 **t=150** 补做 **A4 广播疏散(N7)**，耗时 20 → 完成 170。此时 A3 已于 130 完成，前置条件满足，动作合法。

- 命中权重由 8 升至 10，命中率 100。
- 甄别 80、响应 100、违规 70 不变。
- 总分 = 80×0.30 + 100×0.20 + 100×0.35 + 70×0.15 = 24 + 20 + 35 + 10.5 = **89.5 → 90**。

**反证**：若在 t=100 补做 A4（A3 尚未完成），应被拒绝，命中仍 80，总分**仍为 83**。乙分支在 t=150 的 3 次 A4 尝试正是这一拒绝路径；D4 需用同一规则引擎再验证一次正反例。

## 9. 数据字段提示

- `buildings[].zone`、`floors` 为 v4.1 新增；`floors: null` 表示 GYM 大跨度通高，界面不得把估算高度当实测值展示。
- `junctions[]` 单独列出，`GATE3.kind = "gate"`；不要把它计入楼栋数。
- `road_segments[].from/to` 可指向楼栋或路口；`blocked` 是正式封闭，`hazard` 是自然灾情，二者分开显示。
- `ugc_reports[].event_truth` 只有 `is_real`、`locatable`、`building_id`，**不含路段字段**。
- `fixtures/buildings.json` 是同一地图数据的投影，校验器会与 `canonical-run.json` 逐字段比对，防止两份数据漂移。
