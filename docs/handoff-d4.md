# D4 本地验收与交接

2026 年 11 月 19 日完成 D4 的本地评分和推演界面联调。人工签认待补。

## 接口与使用方式

- `EnginePort.scoreRound(events: readonly RunEvent[]): RoundScore` 使用剧本、动作目录、上报和本轮已确认流水计算四项分数。按 `seq` 处理，使用末回合时钟截断，已接受但尚未完成的动作仍留在账本里，待完成动作无响应和命中分。
- `drill.submitSort(ids)` 在末回合接受一次不同且已投放的上报 ID 序列，沿用统一事件序号，正常剧本提交三项。排序可跳过，排序和定位各自核对，四项总分独立计算。
- `drill.finishDrill()` 在末回合冻结写入和真实用时。页面立即调用评分接口，显示四项分值、漏做动作、首报响应与违规序号，并提供跳转至流水和逐条判读。结算后可回看此前节点，返回末回合可读完整复盘。
- 判读以最后一次提交时所在判断窗为准，改判保留前次 `seq`。原因和位置参考在结算后揭示。重复违规沿用 D1 口径，同一动作同一对象的首条拒绝及成功重试均不扣分，后续拒绝每次扣 15。
- 示例回放继续使用 D1 基线查询 `getScore(runId, events?)`。推演评分入口直接消费本轮流水，无需样例运行编号。

## B 轨独立复验

1. 从 Git 拉取交接版本，运行 `npm ci`、`npm run check:d4`、`npm run build`。`check:d4` 会连带复跑 D3 与更早的回归。
2. 运行 `npm run preview`，打开终端显示的本地地址。在「推演」入口按标准流水的时点提交判读、动作和排序，在 T+300 点击「结束推演并查看评分」。[标准流水说明](../fixtures/canonical-run.md)
3. 在桌面与 375px 复核上表四例。D3 一并复核同秒资源竞争、回看只读，以及 T+140 提交 A5 封闭备用路后路径不可达的用例。[D3 操作与截图](qoder-evidence/D3-2026-11-18-action-engine.md)
4. 记录所测提交、浏览器与屏宽、分项与总分及异常。B 轨签认以独立运行结果为准。
