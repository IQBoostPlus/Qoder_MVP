## 0. 设计准绳

官方未公布评审维度权重。已知机制为：**初筛由评委从每赛道筛出 14 队进决赛**（共 42 队），决赛 12/1–12/15 线上直播路演。因此本规格按两条最稳的准绳设计：

1. **陌生人能独立 3 分钟跑通一次完整推演**——对应赛题要求的「怎么用，5 步以内，评委照着能自己打开用起来」。
2. **开发过程能被举证**——对应赛题要求的「用 Qoder 做出来的过程，尽量多包含截图凭证」。

Hack4Good 是三个赛道中最拥挤、最同质化的一个（无障碍、教育、环保、医疗、防灾都会挤在此），因此差异化不靠功能数量，靠「**能被人当场玩懂的完整闭环 + 可举证的 AI 边界设计**」。

## 1. 一句话定义

> 打开网页、免登录点「开始推演」，AI 扮演导调员抛出复合灾情与噪声上报，学员在校园地图上排布处置动作，系统确定性打分并生成复盘——把「新人第一次面对火灾+内涝会慌」这件事，搬到一个可以反复练、留得下记录的安全环境里。

**核心区分**：这是训练引擎与组织知识沉淀器，不是实时指挥系统，不是室内导航工具。

## 2. 范围决策（v1 → v2）

| 原规划项 | v2 处理 | 理由 |
|---|---|---|
| 复合灾情生成器 | **P0 保留** | 闭环入口 |
| 信息噪声模拟器 | **P0 保留** | 最独特的卖点，不砍 |
| 决策记录与评分 | **P0 保留**，评分改**确定性算法** | 评委必问「分数哪来的」 |
| 复盘教练（跨历史挖掘） | **降级**为单次推演复盘，并入评分模块 | 13 天内无足够历史数据可挖 |
| 成长曲线看板 | **P2 可选**：3 点折线 + 3 条预置示例记录 | 空看板比没有更减分 |
| Agent 四步流水线 | **拆掉**：路径规划改 Dijkstra，不进 LLM | LLM 算几何必错，Few-shot + Schema 只能约束格式不能约束正确性 |
| 双角色（导调员 + 学员） | **合并**：AI 当导调员，导调参数做成折叠面板 | 否则违反「评委 5 步可用」 |
| 训练效果指标（≥85% 等） | **整节删除** | n=5、无对照组、无统计检验，写进材料即成硬伤 |
| 2 场完整桌面推演 | **降级**为 1 场 30 分钟微推演 + 录屏 | 约行政部门排班不可控，不能进关键路径 |
| 移动端适配 D6–D7 | **提前到 D1** 建响应式骨架 | 评委大概率手机打开试 |

### 明确不做（写入 README「未覆盖范围」，主动声明优于被追问）

- 多学员同场协作 / 对抗推演
- 真实 IoT、监控、传感器、指挥通信对接
- 跨机构案例库与检索
- 账号权限体系（免登录 + 本地 session）
- 训练效果的统计显著性验证（列为赛后研究计划）

## 3. 核心流程（评委路径，5 步 ≤3 分钟）

```
① 公开链接 → 首屏免责声明 + 免登录「开始一次推演」
② 选场景卡（3 张预置）或点「AI 随机生成」
③ 推演页：左/上地图，右/下信息流；AI 按时间轴抛灾情与 UGC
④ 点楼栋 → 选处置动作（派队/警戒/断电/上报/广播）→ 时间轴推进
⑤ 结束 → 复盘页（决策时间线 + 失误标注 + AI 点评）→ 存入「我的档案」
```

## 5. 功能需求

### FR-1 场景与数据

- **1.1** 预置 3 个场景模板：
  1. 夜间宿舍楼火灾 + 暴雨内涝
  2. 实验室危化品泄漏 + 人员失联
  3. 体育馆活动散场踩踏风险 + 通讯中断
- **1.2** 每模板含：起因地、蔓延/恶化条件、**≥2 个「预案外意外变量」**、critical 待办项清单（作为评分依据）。
- **1.3** 楼栋数据 **≥25 栋**，字段含名称、类别、估算容量、风险标注（变电/燃气/实验室）、邻接关系。

### FR-2 剧本生成（LLM）

- **2.1** 输入 = 模板 + 干扰因子 + 真实楼栋清单；输出强约束 JSON：起火楼栋 id、时间轴节点数组、UGC 生成指令、critical 项、标准动作集。
- **2.2** 楼栋 id 必须在 DB 中存在；不存在的 id 一律丢弃并重生成。
- **2.3** Schema 校验失败自动重试 1 次；仍失败 → 载入该模板的**兜底预生成剧本**。
- **2.4** 任何情况下用户不得看到「生成失败」页。

### FR-3 UGC 噪声

- **3.1** 每场景生成 **10–15 条**，5 类分布可控，每条携带真值标签（真伪 / 优先级 / 准确位置）。
- **3.2** 全部落库带 `is_training = 1` 常量；界面渲染「训练模拟数据」徽标。
- **3.3** 若噪声文本仿写自真实校园语料，README 须说明来源与脱敏方式；「数据隔离」需可举证（独立表 + 界面标注），不能只是口号。

### FR-4 决策与规则

- **4.1** 动作集 **≥8 种**，每种定义适用对象、前置条件、耗时、消耗资源。
- **4.2** 动作合法性由**规则引擎**判定，**不由 LLM 判定**。
- **4.3** 疏散路径由 **Dijkstra** 计算，被阻断路段权重置 ∞；阻断实时反映在地图上。

### FR-5 评分（确定性）

- **5.1** 四项指标：
  - UGC 甄别准确率 = 正确分类数 / 总 UGC 数
  - 首报有效响应时长 = 第一条真事件 UGC → 第一个有效处置动作的时间差
  - 标准动作命中率（critical 项加权）
  - 违规与遗漏计数（如未拉警戒即疏散、向已断电区派电梯车、critical 项未处理）
- **5.2** 加权总分 0–100；前后端同源计算；同一流水重算结果**必须一致**。
- **5.3** 评分逻辑以代码 + 常量表实现，**README 公开权重**。
- **5.4** 评分器与规则引擎是本项目**唯一必须写单测**的两处。

### FR-6 复盘（LLM 仅写文案）

- **6.1** 输入 = 决策流水 + 标准流程 + 评分明细；输出 `highlights` / `mistakes`（每条指向动作序号）/ `suggestions`，严格 JSON。
- **6.2** AI **不得**输出「应当如何指挥真实事件」类表述：提示词层禁止 + 输出层关键词过滤双保险。
- **6.3** 点评必须绑定具体决策序号，不允许泛泛而谈。

### FR-7 留痕与导出

- **7.1** `runs` 与 `run_events` 全量落库。
- **7.2** 支持按 `run_id` 导出 JSON——对应「全流程数字化留痕、迎检可证明」卖点，实现成本极低。

## 6. 质量需求

### 硬性闸门（违反即不合格）

| 编号 | 要求 | 验收方式 |
|---|---|---|
| Q1 | Qoder Sites 公网部署、访问策略 public，无本地文件/压缩包依赖 | 无痕窗口 + 手机访问 |
| Q2 | 评委 **5 步内 / ≤3 分钟**跑通一次完整推演，全程免登录 | 让未参与者实操，不解说 |
| Q3 | **桌面 + 移动控制台 0 报错** | DevTools + 真机，D7 起每轮回归 |
| Q4 | 375px 宽下地图与信息流均可操作（上下分栏，非左右挤压） | iPhone SE / 375 模拟器实测 |
| Q5 | LLM 永不成为单点：Schema 约束 → 重试 → 兜底剧本三级降级 | 手动断掉 Agent 调用仍能演示 |
| Q6 | 单次推演 LLM 调用 **≤4 次**（1 剧本 + 1 批 UGC + 1 复盘 + 1 重试余量） | 计数器打印，控成本防路演中途额度耗尽 |
| Q7 | 首屏 < 3s；剧本生成 < 15s 且有进度反馈 | Lighthouse + 秒表 |
| Q8 | 训练定位三处可见：首屏免责 + UGC 徽标 + 页面水印 | 任意截图可自证 |
| Q9 | DB Schema **D2 结束前冻结**，之后只加不改 | 变更需 A/C 双人确认 |
| Q10 | **Qoder 使用证据链**：D1 起每次关键生成留对话与截图，README 专章 | 帖子内容自查清单 |

### 一般质量要求

- **代码**：单页 ≤300 行；评分权重、动作目录、模板参数全部外置为常量/表，改数值不改逻辑。
- **可访问性**：动作按钮键盘可达；对比度达 WCAG AA；状态变化有文字而非仅颜色。
- **文案**：全程不出现「实时指挥」「真实事件」；术语统一为「推演 / 学员 / 导调」。
- **性能**：地图图层懒加载；信息流虚拟滚动（>30 条时）。

### 强制合规声明（首屏 + 视频开头）

> ⚠️ **重要声明**
> 本系统为纯训练用途的桌面推演沙盘，不用于、也不适用于任何真实应急指挥场景。
> - 所有灾情数据均为模拟生成，不代表真实事件；
> - 学生上报内容为训练专用噪声数据，已与真实渠道隔离；
> - AI 输出仅供推演讨论，不构成任何行动建议；
> - 系统未对接任何真实监控、传感器或指挥通信设备。

## 7. 数据模型

```
campus_buildings(id, name, category, capacity, risk_tag, geo, adjacency JSON)
disaster_templates(id, name, base JSON, twist JSON, critical_items JSON, standard_actions JSON)
action_catalog(id, name, applies_to, preconditions JSON, duration, cost)
scenarios(id, template_id, modifiers JSON, script JSON, source: generated|fallback)
runs(id, scenario_id, started_at, elapsed, score JSON, status)
run_events(id, run_id, seq, t_offset, kind: disaster|ugc|action|verdict, payload JSON)
ugc_reports(id, run_id, noise_type, text, truth_label JSON, is_training=1, judged_at)
```

### AI 边界（技术叙事的核心一句话）

**符号层管正确性**（Dijkstra 路径、规则引擎合法性、确定性评分）；
**生成层管多样性**（剧本组合、噪声文本、复盘语言）。

这条边界既解决了原规划中「AI 生成内容不稳定」风险的真正来源，也是路演时最能体现工程判断力的部分。
