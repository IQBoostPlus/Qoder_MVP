- 提出：B（界面轨），2026-11-22。接收：A（引擎/生成轨）。
- 关联凭证：[D6 B 云同步与公网发布 §8/§9](qoder-evidence/D6-2026-11-21-b-cloud-publish.md)。
- 状态：云同步写入已闭环（首写 200 活体通过）；真实 AI 生成开关已开但**当前持续回退预置**，需 A 先修通链路，再按本需求扩展新颖度。

## 0. 一句话诉求

用户期望「AI 能生成新剧本」，而不是「在 3 个固定模板里只改时间/地点」。经核实：**引擎通用、契约管形状不管具体故事**，所以扩展可行且不必动冻结契约；但当前生成链路本身没通，且「全自由生成」可靠性风险高。故分三级：**P0 修通 → R1 本期扩新颖度（推荐）→ R2 全自由生成（演进，不在本期承诺）**。

## 1. 现状根因（实测，非推断）

- 生成提示词 `generationPrompt`（`server/generation-provider.ts:17`）只让模型输出 `candidate`：`start_building_id / road_id / first_report_at / confirmed_at / escalation_at / t_end / perspective` 七个参数。
- `assembleBundle`（`src/scenario-generation/bundle.ts:95`）把剧情写死：10 条上报的类别、相对时刻偏移、真假、判断窗、优先级（4/8/7/1/6/10/2/3/9/5）、标准动作序列均由模板固定；上报文字 = 模板句 + 楼栋/路名。模型只选「哪栋楼/哪条路/4 个时刻/哪种视角」。
- **引擎不是瓶颈**：`judgeAction / scoreRound / 路径规划` 对任何符合契约形状的 `ScenarioBundle` 都能判分；`validateBundle` 只校验结构（地图引用、10 条上报优先级唯一、判断窗自洽、节点严格递增且末节点=t_end 等），不要求必须是现有 3 模板。模板是生成期保证「合法可玩」的脚手架。
- **当前链路故障**（凭证 §9）：登录态请求到达服务，但 `ensureResources` 首个上游调用 `GET /api/v1/cloud/models`（`api.qoder.com.cn`）失败 → `fallback_reason=network / calls=0 / not_sent`，Storage 绑定 `model:null, reason:network`。PAT 存在（否则 not_configured），域名正确，非 401/403 鉴权拒绝。另：生成桶名 = SHA-256(空串)，网关 `user_id` 为空。

## 3. R1 · 本期扩新颖度（推荐，A+B 组合，低风险）

目标：观众能明显看到「每次不一样、AI 在写内容」，同时合法性有校验兜底、失败可回退。

### R1-a 扩充模板集（A）
- 在 `src/scenario-generation/templates.ts` 增加模板（不同灾种/楼栋/路线/上报变体），形状与现有一致。
- `assembleBundle` 无需改结构即可消费新模板；`validate-d5/d6` 按模板迭代，新增为加法。
- 入口 `ScenarioStart.vue`（B）展示更多可选模板。
- 验收：≥N 套模板（N 待 A 定，建议 5~6）均可预置运行且固定评分回归不变；新模板各自合法可玩。

### R1-b 放开上报文案为「受约束改写」（A 主，B 配合）
- 现状：D6 `reports.ts` 的 `validateReportBatch` 要求 text ∈ 白名单候选（原句或类别前缀+原句），模型只能选不能写。
- 需求：保留骨架（类别/真假/判断窗/优先级/时刻/地点/确认状态由模板固定），允许模型**自由改写 10 条上报文字**，但必须通过**事实保全校验**：
  - 不得新增/删除现场事实、地点、确认状态；不得改变 `event_truth`（is_real/locatable/building_id）与 `judgment_windows`（expected/reason 语义）；
  - 实体（楼栋/路名）、否定（「不实/已核实为水蒸气」）、重复关系必须保留；
  - 至少一条与预置首项不同（沿用现规则）。
- 实现要点：`validateReportBatch` 从「精确白名单匹配」升级为「事实一致性校验」（A 设计校验器，可基于槽位事实关键词/否定/地点的保全面，而非逐字）；校验失败→共享 retry→仍失败回退该剧本预置 10 条（沿用现回退链）。
- 预算：与剧本共享 15 秒/4 槽（沿用）。
- 验收：模拟与真实批次下，上报文字明显多样但事实/真值/判断窗与槽位一致；非法改写被拒并回退；固定样例 83/44/90/83 不变。

### R1 分工
- A：模板扩充、事实保全校验器、生成/回退逻辑、`validate-d5/d6` 用例。
- B：入口多模板展示、AI 徽标与回退透明文案、登录引导（见 §5）、双视口走查与凭证。
- 互不阻塞：A 改生成层时 B 用预置/模拟继续界面工作。

## 4. R2 · 全自由生成（演进方向，D7/赛后，本期不承诺）

- 做法：模型直接产出完整 `ScenarioBundle`（nodes/events + 10 条上报含真值与判断窗 + standard_actions/critical_items），`validateBundle` 严校验 + 平衡/可行性检查 + 重试 + 失败回退模板。
- **不必动冻结契约**（契约管形状）；改的是生成层提示词/组装/校验。
- 风险声明（必须向用户明示）：
  1. LLM 在 15 秒内产出「合法+平衡+可玩」完整剧本失败率高 → 演示可能频繁回退；
  2. 教学平衡性（判断窗设计、动作关键性）失去模板保证，可能过易/不可解；
  3. token/延迟大增，更易撞预算与超时；
  4. 需要强 schema 引导 + 多层校验 + 重试预算，工程量显著。
- 结论：作为赛后/D7 研究项；若用户坚持本期做，需单独授权并接受回退风险与时间盒，且 P0/R1 先就绪。

## 5. 声明与边界（双方遵守）

1. **冻结契约不动**：`src/contracts.ts`、`fixtures/*.json`、`db/schema.sql`、`scripts/validate-*.ts` 基线零改动；R1/R2 改生成层（`generation-provider.ts`、`bundle.ts` 组装、`reports.ts` 校验、`templates.ts`），不改引擎判分/规则/路由。
2. **引擎通用性前提**：扩展依赖「引擎对任意合法剧本包可判分」这一已核实事实；若 A 发现引擎隐含模板假设，须先提出再议。
3. **合法性与回退诚实**：任何生成结果先校验后挂载；失败回退预置并在界面诚实标注（B 负责文案），不得把回退伪装成 AI 生成。
4. **登录门槛**：生成路由需登录用户（`user_id` 预算隔离）。匿名访客回退预置。B 将加「登录后可用 AI 生成」引导（401 不再静默回退）。**是否允许匿名生成 = 破坏预算隔离的跨轨决策，待 A/用户显式拍板，本期默认保持登录门槛。**
5. **预算与成本**：真实发送计费；B 站独立台账，不占 A 的 Stage 3 额度；每轮 4 槽上限沿用；任何真实发送需用户授权，首发只 1 次验证。
6. **分工**：A 拥有生成/引擎/校验/台账；B 拥有界面/入口/徽标/走查/凭证。两轨互不阻塞。
7. **凭证**：每步留「想完成什么/做了什么/如何验证」+ 截图；生成验收须含台账 sent/complete、calls、selection、复算一致；脱敏（PAT/Session/密钥/签名 URL 不出现）。
8. **时间盒**：距 11/27 剩 5 天。P0 优先；R1 本期落地；R2 不在本期承诺。真人试用（T1 五步达标）仍为独立计分项，不被本需求挤占。
